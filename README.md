## 概要
ノードベースのキャンバス上で、複数のAIモデルを使って画像・動画を生成し、チームで素材を管理・共同編集できるWebアプリです。実際に社員が日常業務で使う **本番ツール** として運用されています。

## 技術スタック
| 領域 | 使用技術 |
|---|---|
| フロントエンド | Next.js（App Router）/ TypeScript / React Flow / TipTap |
| バックエンド | Next.js API / Prisma / PostgreSQL / Redis + BullMQ（ジョブキュー） |
| クラウド | Railway（アプリ・ワーカー）/ Cloudflare R2（オブジェクトストレージ） |
| 生成AI | 用途に応じて複数の画像・動画生成モデル、LLM を API 連携 |
| 認証 | Google OAuth + WebAuthn/パスキー（多要素認証） |

## アーキテクチャ（概要）
- **Webアプリ**（Next.js）＝ UI と API
- **バックグラウンドワーカー**＝ 時間のかかる生成処理をキュー（BullMQ/Redis）で非同期実行
- **オブジェクトストレージ**（R2）＝ 生成物・アップロード素材を保管、DBにはメタ情報のみ
- 用途ごとに最適なクラウド／APIを選定・連携する **マルチクラウド構成**

## 主に取り組んだこと

### 🔒 セキュリティ（認証・アクセス制御）
- Google ログインに加え、**WebAuthn/パスキーによる多要素認証**を導入。Google認証だけではアプリを使えず、パスキー確認を必須にする2段構え。
- 認証状態は **サーバー発行の署名付きCookie** で管理し、クライアント側からの自己昇格を防止。重要操作には **直近の再認証（step-up）** を要求。

### ☁️ マルチクラウド / クラウドネイティブ
- アプリ・ストレージ・生成APIを役割ごとに分離し、複数クラウドを連携。
- 生成物はストレージへ、参照はURL＋メタデータで扱う設計で、DB肥大化を避けつつ拡張しやすい構成に。

### 🤖 生成AIの実務統合
- 複数の生成AIモデルを **用途に応じて切り替え可能** な形で組み込み。
- LLMで入力内容を自動チェックする仕組み（不適切・権利面のプリチェック）を実装し、「安全に・便利に」生成AIを使えるようにした。

### 📊 運用・可観測性
- モデル別の利用状況を可視化するダッシュボード、外部APIの残高切れを検知してチームへ自動通知する仕組みなどを実装。

## 開発の進め方（プロセス）
機能そのものだけでなく、**どう進めたか**を大切にしました。

### 1. 設計へのこだわりと競合研究
- 既存の類似サービスを実際に触って調査し、優れたUI・機能の「なぜ良いのか」を分解して設計に反映。
- 海外で新サービスが出た際もすぐにチェックし、取り入れられる要素を継続的に研究しながら開発。
- 「まず簡潔に・最小の変更で最大の効果」を原則に、作り込みすぎない設計判断を意識。

### 2. ユーザーフィードバックの反映
- 開発は1人だが、**実際に使う社内ユーザーの声を定例ミーティング等で継続ヒアリング**し、毎回の改善に反映。
- 「ここが分かりにくい」「この比率にしたい」といった現場の具体的な要望を、そのまま仕様に落として素早く反映。
- **1機能＝1つの小さな変更単位**で、レビュー→確認→反映を細かく繰り返し、**本番で使われているツールを止めずに**継続改善。

### 3. AIの活用と技術的な課題解決・コラボレーション
- 知識が足りない領域は **徹底的に調べ、AI（Claude 等）を"壁打ち相手"** として、設計相談・実装・デバッグ・コードレビューを高速に反復。
- 一方で、**製品としての判断・優先順位づけ・ユーザー要望の翻訳・最終確認は自分の責任**で行い、「AIに任せきりにしない／使いこなす」ことを重視。
- **根本原因まで理解してから直す**（その場しのぎにしない）を徹底し、同じミスを繰り返さないよう学びを記録する習慣も運用。
- 難所は **社内エンジニアにも相談**し、アドバイスをもらいながら実装を前進。

## 学んだこと
- 実運用に耐えるWebアプリを、**要望→設計→実装→リリース**まで一貫して回す力
- 設計段階からセキュリティを組み込む重要性（**Secure by Design**）
- 複数クラウド／外部APIを **適材適所** で組み合わせる判断
- **AIを開発の相棒として使いこなす力**（調べる・壁打ち・レビュー）と、人（ユーザー・エンジニア）との協働の両立
- 非エンジニア出身でも、**主体的に学び・巻き込み・作り切る**ことでプロダクトを前に進められること
